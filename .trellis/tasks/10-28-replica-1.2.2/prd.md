# 异度神剑 2 Wiki Android：功能对齐原版 1.2.2，视觉自研

## Goal

功能上对齐原版 APK 1.2.2（`cn.xenoblade2.wiki`），做到可手测；视觉上必须是自研设计语言，不能与原版雷同，避免抄袭争议。功能对齐验收通过后，按顺序做路线规划、开环明确化、Agent。

用户要的是能在模拟器里点的界面。每轮改动都要 `assembleDebug`、安装、截图对照。

## Background

- 原版未开源。对照材料是 `src/jadx/` 反编译、`apk/` 提取资源和实机截图。这些目录不进 git，只用于确认「有哪些功能和交互」。
- 现有工作区把原版视觉搬了过来：`ui/theme/Theme.kt` 直接用原版的 PyraRed `#D40011` + MythraGold `#FFC107` 白卡体系；`assets/regions/` 是原版 Titan 插画；地图 marker 用 `assets/maps/*-marker.*` 原版位图。这些都要换掉。
- 本地库已有任务、异刃、地图和点位。`route_connection` 为空，采集点映射和室内图拟合不完整，见 Known Limitations。

## Requirements

1. **功能对齐**：原版有的查询、筛选、收藏、地图和设置都要能用。20 个功能都保留，但收进图鉴的四个分组；底部是图鉴 / 地图 / 记录 / 设置，不再照搬原版 5 tab。没有数据的入口进占位，不造假数据。
2. **视觉自研（硬性）**：配色、卡片结构、图标风格、字体与间距节奏必须自成一套，不能逐像素复刻原版。判定标准见 Acceptance Criteria 第 2 条。
3. **地图资源来自 xenoblade2.cn**：底图、点位图标和点位坐标以该站为参考。原版 APK 的 Titan 插画和 marker 位图不进界面。使用站点内容须遵守 CC BY-NC-SA 4.0，并署名「乐园数据管理室 https://xenoblade2.cn」。
4. **数据可参考 `https://xenoblade2.cn/`**：用于补全图鉴数据和类别图标。使用其图标须署名「乐园数据管理室 https://xenoblade2.cn」，许可 CC BY-NC-SA 4.0。
5. `layered-maps` 属于功能对齐的一部分：同一 Area 的分层图分开，点位必须落在对应层的图内。
6. 功能对齐验收通过后才做 `route-planning`：计划地图只画最近传送点或标志性建筑、计划点和路径；点不能画到地图外。没有路网时标明是示意折线，不承诺寻路。
7. 然后做 `affinity-clarity`：开环节点写出需求、获取途径和关联任务；缺数据就写暂无，不编造。
8. 最后做 `agent-integration`：用 App 内数据做规划和问答，结果可保存成计划。模型只能标注推测，不能补出不存在的路网或坐标。

## Acceptance Criteria

- [ ] 功能清单逐项可用：20 个功能都能从四个分组到达，异刃筛选、任务四大类、怪物筛选、地图分层和设置可用。
- [ ] 视觉评审通过：与原版同分辨率截图并排，主色体系、卡片结构、图标风格、字体与间距节奏四项里至少四项明显不同，且不出现原版视觉资源。
- [ ] 底部是图鉴 / 地图 / 记录 / 设置。设置里置顶的图鉴入口重启后仍在。
- [ ] 浮动操作区是自研样式，不照搬原版的红金圆形按钮组合。
- [ ] 地图筛选用自研交互；点位按类型使用 xenoblade2.cn 的 marker 图，不只换颜色。
- [ ] 抽查一张多层地图，点位不落在图外，切层后只显示该层。
- [ ] 功能对齐完成前，不把路线规划、开环改写或 Agent 当成当前交付。
- [ ] 之后：一份任务计划在地图上只显示最近传送点或地标、计划点和路径。
- [ ] 之后：一个异刃开环节点能看到需求、获取途径和跳转；没有映射时显示暂无。
- [ ] 之后：Agent 能读任务、异刃、地图并保存计划；回答区分数据库事实和模型推测。
- [ ] `files/plans.db` 里已有计划不丢失。密钥只在模拟器 SharedPreferences，不进入仓库。

## Constraints

- 反编译 Java 不复制进 `app/`，也不提交 `apk/`、`src/`。
- 不接友盟、广告 ID、更新检查或远程数据库下载。
- 不引入新 UI 框架，继续用手写导航栈和 Compose。
- API key、endpoint、model 名若含密钥，只存 SharedPreferences。

## Out of Scope

- 逐像素复刻原版界面。
- 在功能对齐验收前继续加路线算法、开环文案生成或 Agent 工具。
- 用大模型假装补齐空的 `route_connection`、缺失采集映射或拟合失败的室内图。
- 商用 xenoblade2.cn 图标。

## 算错时的处理

坐标只从站点的 `Mapinfo` 和 `Gmk` 计算。结果不对时不让大模型改数字。

- 点落在地图外，或投到了错误的层：这张图上不画这个点，步骤里标明「不在当前层」。换层后再算。
- 一个物品对应多个采集点：348 种采集物里 332 种不止一个点。步骤写了地区就只保留该地区的点，全部标成候选，不假装只有一个正确答案。用户点选后记在本地计划里，下次不算回去。
- 步骤没写物品名：不钉点。能从站点任务页提取到物品或地点再用上一条；提取不到就显示「步骤没写采集什么」。
- `ma07a_b_floor_B01` 的 4 个采集点没有地图范围：只出现在列表里，不画到别的层上。

## Known Limitations

- `route_connection` 为空，只能最近邻排序，不能做真实寻路。
- 采集点坐标站点里基本都有：`JSON:Gmk/collection` 1530 条都有坐标，和本地 `collection_code` 对上 1528/1532。本地没钉上的 503 个里，499 个能用这批坐标补上。1526/1530 能直接投到站点底图，剩下 4 个落在缺少 `Mapinfo` 的 `ma07a` 层。
- 以前说的「采集落点约 32%」指的是任务步骤文案，不是采集点缺坐标。155 条 Collect 步骤里，不少只写「去收集材料」，正文没有物品名，所以还是不知道该钉哪个点。
- 以前说的「76 张图只有 41 张能拟合」指的是 FrontierNav 像素拟合。站点是另一套图，90 张都带官方坐标范围，不需要那次拟合。
- 大模型只能在路网和没写物品名的步骤上做标注过的推测，不能当成已经实现。
